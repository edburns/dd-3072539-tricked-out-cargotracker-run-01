## Implement

Modify:

- `demo/src/main/java/org/eclipse/cargotracker/application/BookingService.java`
- `demo/src/main/java/org/eclipse/cargotracker/application/internal/DefaultBookingService.java`
- `demo/src/test/java/org/eclipse/cargotracker/application/BookingServiceTest.java`
- `1-trick-out-01-remove-before-merge/evidence-matrix.md`

Add this application API:

```java
void changeDeadline(TrackingId trackingId, Date deadline);
```

Implement it by:

1. Loading the cargo with `cargoRepository.find(trackingId)`.
2. Reading the current destination from `cargo.getRouteSpecification().getDestination()`.
3. Constructing a replacement `RouteSpecification` from `cargo.getOrigin()`, that destination, and the supplied deadline.
4. Calling `cargo.specifyNewRoute(routeSpecification)`.
5. Calling `cargoRepository.store(cargo)`.
6. Logging the tracking ID and new deadline at `Level.INFO` in the established `changeDestination(...)` style.

Write the test first. Append ordered `testChangeDeadline()` after `testChangeDestination()`. Create a deadline one month after the test's original deadline, invoke the service, and reload through the injected repository. Assert the origin is Chicago, destination is Helsinki, the stored deadline has the requested calendar day, and the assigned itinerary is unchanged. Also assert transport status `NOT_RECEIVED`, last known location `Location.UNKNOWN`, current voyage `Voyage.NONE`, not misdirected, ETA `Delivery.ETA_UNKOWN`, next activity `Delivery.NO_ACTIVITY`, not unloaded at destination, and routing status `MISROUTED`.

Update the evidence matrix after implementation and validation with the exact commands and results.
