The resolved interaction mirrors Change Destination: a serializable session-scoped JSF managed launcher opens a PrimeFaces dynamic dialog, while the issue 3 view-scoped CDI editor owns load and submit. Research established a MyFaces compatibility requirement: `<f:metadata>` must be a direct child of the root `<html>`, before `<h:head>` and `<h:body>`. The dialog receives one `trackingId`, is modal and draggable, not resizable, measures 410 by 280, closes with `"DONE"` on update and `""` on cancel, and requires a non-null date without imposing a chronological rule.

## Implement

Create:

The launcher uses `@ManagedBean(name = "changeArrivalDeadlineDateDialog")` and `@SessionScoped`, is serializable, and implements `showDialog(String trackingId)`, `handleReturn(SelectEvent event)`, and `cancel()`. `showDialog(...)` passes the tracking ID as `Map<String,List<String>>` request data and opens `/admin/dialogs/changeArrivalDeadlineDate.xhtml` with `modal=true`, `draggable=true`, `resizable=false`, `contentWidth=410`, and `contentHeight=280`. `cancel()` closes with `""` and never invokes the facade.

The XHTML title is `Change Deadline`. Put this metadata directly under `<html>` before the head:

```xhtml
<f:metadata>
    <f:viewParam name="trackingId"
                 value="#{changeArrivalDeadlineDate.trackingId}"/>
    <f:viewAction action="#{changeArrivalDeadlineDate.load}"/>
</f:metadata>
```

Display labeled, read-only Origin and Destination values from `changeArrivalDeadlineDate.cargo.originName` and `.finalDestinationName`. Bind a required `p:datePicker` to `.arrivalDeadlineDate`, include visible validation feedback, wire Cancel to `changeArrivalDeadlineDateDialog.cancel()`, and wire Update to `changeArrivalDeadlineDate.changeArrivalDeadline()`. Preserve the established return-handler behavior needed to refresh the calling Administration view after success.

With Liberty running, directly request `/cargo-tracker/admin/dialogs/changeArrivalDeadlineDate.xhtml?trackingId=DEF789`. Prove HTTP 200, the exact title, rendered origin/destination, initialized deadline, successful update, and cancellation without mutation. Check logs for `TagException`, metadata parent errors, `FacesException`, or server errors. Re-test existing destination editing.

Update the evidence matrix after implementation and validation with exact commands, HTTP/UI evidence, and results. Stop Liberty cleanly.
